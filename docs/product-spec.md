# 마음 상태 확인 + 감정 일기 MVP 기획 문서

## 1. 제품 개요
- 이 서비스는 사용자가 지금의 마음 상태를 가볍게 돌아보고, 하루에 한 번 감정 일기를 남기면서 스스로를 이해할 수 있게 돕는 서비스예요.
- 진단이나 해결을 앞세우기보다, 상태를 파악하고 기록하고 공감받는 경험을 우선해요.
- 사용자가 앱을 열었을 때 받는 첫 인상은 `검사 앱`이 아니라 `마음을 돌보는 기록 서비스`에 가까워야 해요.

## 2. 제품 목표
- 사용자가 자신의 현재 상태를 부담 없이 확인할 수 있어야 해요.
- 하루에 한 번 감정 일기를 쓰는 루틴을 만들 수 있어야 해요.
- 결과 화면은 불안감을 키우지 않고, 지금 상태를 부드럽게 해석해줘야 해요.
- 위험 신호가 있을 때는 진단명보다 안전 확보와 도움 연결이 먼저 보여야 해요.

## 3. 타깃과 서비스 범위
- 서비스 대상은 한국 거주 성인 사용자예요.
- 국가별 정책이나 다국어 대응은 MVP 범위에서 제외해요.
- 내부 평가에는 우울 관련 세부 분류를 사용하지만, 사용자에게는 진단명 형태로 직접 노출하지 않아요.

## 4. 핵심 사용자 여정
1. 앱에서 카카오 또는 구글로 로그인해요.
2. 회원가입 과정에서 성별과 생년월일을 입력해요.
3. 인증이 끝나면 웹 화면으로 들어와요.
4. 첫 상태 확인 질문을 진행해요.
5. 결과 화면에서 지금의 상태를 설명받고, 필요하면 안전 도움 화면으로 이동해요.
6. 하루에 한 번 오늘의 감정 일기를 써요.
7. 저장 중 위로 문구를 보고, 기록 완료 상태를 확인해요.
8. 기본 4주 후 다시 상태를 확인해요. 다만 상태 변화가 크면 더 빨리 다시 볼 수 있어요.

## 5. 톤 앤 매너
- 서비스 전반의 감성은 `진단`, `분석`, `해결`보다 `공감`, `위로`, `정리`에 가까워야 해요.
- 사용자 문구는 딱딱한 종결형보다 부드러운 구어체를 사용해요.
- 결과 문구는 확정형 표현을 피하고, 사용자의 상태를 조심스럽게 짚어주는 방식으로 써요.
- 금지 표현 예시:
  - `우울증 검사 결과`
  - `중증 우울 상태입니다`
  - `고위험군입니다`
- 권장 표현 예시:
  - `최근에 많이 버거우셨겠어요`
  - `지친 시간이 조금 길어지고 있는 것 같아요`
  - `오늘 마음을 한 번 더 살펴보면 좋겠어요`

## 6. 로그인과 가입
### 6.1 로그인
- 로그인 방식은 카카오, 구글 2가지만 제공해요.
- 이메일 자체 가입은 MVP 범위에서 제외해요.
- 실서비스 기준 로그인과 회원가입은 네이티브 앱에서 처리해요.
- 웹의 로그인 화면은 개발 확인이나 fallback 용도로만 유지할 수 있어요.

### 6.2 가입 시 수집 정보
- 성별
- 생년월일
- 서비스 약관 및 개인정보 동의

### 6.3 가입 정보 활용
- 성별과 생년월일을 기반으로 불필요한 질문은 보여주지 않아요.
- 예를 들어 남성 사용자에게는 임신, 월경, 산후 관련 질문을 노출하지 않아요.
- 여성 사용자라도 연령상 관련성이 낮으면 주산기 관련 질문은 제외할 수 있어요.

## 7. 상태 확인 기능
### 7.1 기능 목적
- 사용자가 현재 마음 상태를 스스로 점검해보는 기능이에요.
- 의료적 진단이 아니라, 현재 어려움의 양상과 강도를 참고용으로 정리해주는 기능이에요.

### 7.2 진행 원칙
- 질문은 한 번에 하나씩 보여줘요.
- 사용자에게는 `검사`보다 `체크인`에 가까운 인상을 줘야 해요.
- 민감한 질문 앞에는 짧은 완충 문구를 둘 수 있어요.
- 질문 응답 중 위험 신호가 감지되면 이후 결과보다 안전 안내를 우선해요.

### 7.3 질문 구성
- 기본 구조는 PHQ-9 계열 문항을 바탕으로 해요.
- 내부 분류를 위한 보조 질문을 함께 사용해요.
- 선택형 외에 필수 아님 서술형 질문도 2~3개 포함해요.

### 7.4 서술형 질문 예시
- `요즘 가장 자주 마음에 남는 일이 있나요?`
- `최근 나를 버티게 한 건 무엇이었나요?`
- `지금 가장 필요한 도움이 있다면 어떤 느낌에 가까운가요?`

## 8. 결과 설계
### 8.1 사용자에게 보여주는 방식
- 결과는 점수 중심이 아니라 해석 중심으로 보여줘요.
- 사용자는 진단명보다 지금 어떤 어려움이 두드러지는지 이해할 수 있어야 해요.
- 결과 화면은 아래 3가지 요소를 기본으로 가져가요.
  - 현재 상태 해석
  - 다음 행동 제안
  - 필요 시 안전 도움 연결

### 8.2 결과 예시 방향
- `최근에 기운이 많이 빠져 있었던 것 같아요`
- `마음이 오래 지쳐 있었던 흐름이 보여요`
- `혼자 버티기보다 누군가와 함께 살펴보면 좋겠어요`

### 8.3 재확인 주기
- 기본 권장 주기는 4주예요.
- 아래 경우에는 더 빠르게 다시 확인할 수 있어요.
  - 상태가 갑자기 많이 달라졌을 때
  - 큰 사건이 있었을 때
  - 안전 관련 신호가 감지됐을 때
  - 주산기 맥락처럼 더 촘촘한 확인이 필요한 경우

## 9. 감정 일기 기능
### 9.1 목적
- 상태 확인 결과를 일회성으로 끝내지 않고, 하루 단위 기록으로 이어지게 해요.

### 9.2 작성 규칙
- 하루에 한 번 작성할 수 있어요.
- 오늘의 감정 3개는 필수예요.
- 그 외 본문은 자유롭게 적을 수 있어요.

### 9.3 저장 경험
- 작성 완료 후 저장하는 동안, 오늘 선택한 감정을 기반으로 한 위로 문구를 보여줘요.
- 저장이 빨리 끝나더라도 위로 문구는 최소 1초 이상 보여줘요.
- 위로 문구가 사라진 뒤 오늘 기록 완료 상태를 확인할 수 있어야 해요.

## 10. 내부 평가와 사용자 노출 분리
- 내부적으로는 우울 관련 세부 갈래를 나눠서 결과를 저장해요.
- 사용자에게는 그 분류명을 직접 보여주지 않아요.
- 사용자 화면에서는 `무엇 때문에 힘든지`, `얼마나 오래 이어지는지`, `지금 도움이 필요한지`를 부드럽게 번역해서 보여줘요.

## 12. 단기성 / 장기성 구분
- 단기성 흐름:
  - 특정 사건 이후 시작된 경우
  - 2주 이상이지만 장기 반복 근거가 부족한 경우
  - 비교적 최근 변화 중심인 경우
- 장기성 흐름:
  - 2년 이상 지속감이 있는 경우
  - 비슷한 우울 흐름이 반복되는 경우
  - 오랫동안 기능 저하나 무기력이 누적된 경우

## 13. 안전 정책
- 위험 신호가 감지되면 결과 해석보다 안전 확보를 우선해요.
- 한국 기준 도움 리소스를 우선 제공해요.
  - 자살예방상담전화 `109`
  - 응급전화 `119`
  - 보건복지상담센터 `129`
- 안전 화면은 사용자가 혼자 판단하게 두지 않고, 바로 연결 가능한 행동 버튼을 보여줘야 해요.

## 14. MVP 이후 확장 메모
- 주간/월간 감정 흐름 요약
- 감정 태그 기반 개인화 위로 문구 고도화
- 전문가 연결 연계 기능
- 보호자 또는 신뢰인 공유 플로우
