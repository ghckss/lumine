# Lumine 추후 기능 플래닝

## 1. 문서 목적

이 문서는 현재 구현된 Lumine을 기준으로, 추후 제품 로드맵에서 검토할 기능 후보와 우선순위를 정리한다.

## 3. 2순위: 재방문을 만드는 기능

### 3.1 기록 리마인더

- 사용자가 원하는 요일과 시간에 감정 일기 알림을 설정할 수 있게 한다.
- 마음 상태 재확인 권장일에 알림을 제공한다.
- 알림 시간, 요일, 문구, 활성 여부를 직접 설정할 수 있게 한다.
- 사용자가 연속으로 기록하지 않으면 압박하지 않도록 알림 빈도를 낮춘다.

### 3.2 주간·월간 마음 리포트

리포트에는 다음 내용을 포함한다.

- 기록한 일수
- 자주 느낀 감정
- 이전 기간과 비교한 변화
- 마음이 무거웠던 날과 편안했던 날
- 마음 상태 확인 결과의 변화
- 다음 기간에 해볼 수 있는 작은 행동 한 가지

현재 홈의 7일 기록을 재방문 가치가 있는 정기 리포트로 확장한다.

### 3.3 달력형 기록 탐색

- 월간 달력에서 기록 여부와 대표 감정을 표시한다.
- 감정별 필터를 제공한다.
- 기간별 기록 조회를 제공한다.
- 일기 본문 검색을 제공한다.
- 특정 감정이 나타난 날만 모아서 볼 수 있게 한다.

## 4. 3순위: Lumine 차별화 기능

### 4.1 감정 맥락 태그

일기 작성 시 다음 맥락을 선택적으로 기록할 수 있게 한다.

- 수면
- 에너지
- 일·학업
- 가족·연애·대인관계
- 건강
- 생리·임신·출산
- 날씨 또는 계절

이를 통해 단순한 감정 빈도를 넘어 어떤 상황에서 감정이 반복되는지 설명할 수 있게 한다.

### 4.2 개인화된 작은 행동

결과 화면의 추천 문구를 실제로 실행하고 피드백할 수 있는 행동 카드로 확장한다.

- 오늘 해볼 행동 하나를 선택한다.
- 행동 완료 여부를 기록한다.
- 행동이 실제로 도움이 되었는지 피드백한다.
- 도움이 되었던 행동을 이후 결과에서 우선 추천한다.

예시 흐름:

`10분 산책하기 → 완료 → 마음이 조금 나아졌어요`

### 4.3 개인 안전 계획

위기 상황이 발생하기 전에 사용자가 자신의 안전 계획을 미리 설정할 수 있게 한다.

- 나에게 나타나는 위험 신호
- 나를 진정시키는 행동
- 믿을 수 있는 사람 1~3명
- 자주 이용하는 상담기관
- 위기 시 전화 또는 메시지 빠른 전송
- 위험 응답 이후 일정 시간 뒤 안전 상태 재확인

현재의 109·119·129 연결 기능을 개인화된 안전망으로 발전시킨다.

### 4.4 스마트워치 기반 마음 체크인 제안

사용자가 명시적으로 동의한 경우 Apple Watch 또는 Wear OS 기기에서 수집된 건강·활동 데이터의 변화를 바탕으로 감정 일기나 마음 상태 확인을 제안한다.

이 기능의 목적은 스마트워치 수치로 정신 건강 상태를 진단하는 것이 아니다. 사용자의 평소 생활 패턴과 다른 변화가 일정 기간 관찰될 때, 자신의 상태를 직접 돌아볼 수 있는 계기를 제공하는 것으로 한정한다.

#### 활용 후보 데이터

- 수면 시간과 수면 시간대의 변화
- 안정 시 심박수의 변화
- 심박 변이도(HRV)의 변화
- 걸음 수와 활동량의 감소
- 호흡수 등 기기와 플랫폼에서 안정적으로 제공하는 보조 지표

단일 측정값이나 모든 사용자에게 동일한 고정 임계값은 사용하지 않는다. 최소 1~2주의 개인 기준선을 만든 뒤 최근 2~3일 동안 둘 이상의 지표가 평소 범위를 벗어났을 때만 제안을 검토한다. 데이터가 부족하거나 기기별 측정 품질이 낮은 경우에는 알림을 보내지 않는다.

알림 예시:

> 최근 수면과 활동 패턴이 평소와 조금 달라요. 1분만 지금 마음을 기록해 볼까요?

알림을 누르면 오늘 작성한 일기가 있는 경우 수정 화면으로, 없는 경우 신규 작성 화면으로 이동한다. 사용자는 알림 빈도를 조절하거나 기능을 언제든지 끌 수 있어야 하며, 알림 화면에서 제안 이유를 확인할 수 있어야 한다.

#### 플랫폼 구현 방향

- iOS에서는 Apple Watch가 기록한 데이터를 iPhone의 HealthKit을 통해 읽는다. `HKObserverQuery`와 백그라운드 전달을 사용할 수 있지만 시스템 상황에 따라 전달 시점이 늦어질 수 있으므로 실시간 감지로 설계하지 않는다.
- Android에서는 Health Connect를 통해 연결된 건강 앱과 워치 데이터를 읽고, 별도 권한과 WorkManager를 사용해 주기적으로 변화를 확인한다.
- Wear OS 전용 앱을 추가하는 단계에서는 Health Services의 `PassiveMonitoringClient`를 사용해 저전력으로 활동·심박 데이터를 관찰할 수 있다.
- 초기 알림은 스마트폰 로컬 알림으로 제공하고 워치의 알림 미러링을 활용한다. 워치에서 직접 감정을 선택하거나 체크인하려면 watchOS·Wear OS 컴패니언 앱을 별도로 개발한다.
- React Native 화면과 비즈니스 로직은 공유하되 HealthKit, Health Connect, 권한, 백그라운드 처리는 각 플랫폼의 네이티브 모듈로 구현한다.

관련 공식 문서:

- [Apple HealthKit Observer Queries](https://developer.apple.com/documentation/healthkit/executing-observer-queries)
- [Android Health Connect 데이터 읽기](https://developer.android.com/health-and-fitness/health-connect/read-data)
- [Wear OS Health Services](https://developer.android.com/health-and-fitness/health-services)

#### 개인정보 및 안전 원칙

- 건강 데이터 종류별 접근 목적과 사용 방식을 권한 요청 전에 설명한다.
- 1차 버전에서는 원본 건강 데이터를 서버로 전송하지 않고 기기 안에서 기준선과 알림 조건을 계산한다.
- 서버에는 가능하면 원본 수치 대신 알림 발생 여부와 사용자의 선택적 피드백만 저장한다.
- 권한 철회, 데이터 삭제, 알림 중지 경로를 설정 화면에서 명확하게 제공한다.
- 심박수나 수면 변화만으로 우울·불안·위기 상태를 판정하거나 진단명과 위험 점수를 표시하지 않는다.
- 워치 데이터만으로 위기 알림이나 긴급 연락을 자동 실행하지 않는다.
- 불안감을 조성하는 표현과 반복 알림을 피하고, 무응답 시 알림 빈도를 낮추는 쿨다운을 적용한다.

#### 단계별 도입안

1. HealthKit·Health Connect 권한 및 데이터 가용성 확인
2. 하루 1~2회 온디바이스 분석과 로컬 알림 제공
3. 알림에서 감정 일기 또는 마음 상태 확인으로 연결
4. 개인 기준선, 복수 지표 조건, 쿨다운과 제안 이유 표시
5. `도움 됐어요`, `지금은 아니에요` 피드백을 통한 알림 정책 개선
6. 충분한 사용성과 안전성 검증 후 워치용 간단 체크인 앱 검토

도입 전에는 사용자별 서버 데이터 격리, 영속 데이터베이스, 건강 데이터 동의·철회·보관·삭제 정책을 먼저 운영 수준으로 갖춘다.

## 5. 4순위: 장기 확장 후보

- 감정 일기와 마음 상태 확인 결과의 장기 변화 비교
- 사용자가 선호하는 위로 문구 스타일 설정
- AI 위로 문구에 `도움 됐어요` 또는 `아니에요` 피드백
- 상담 시 활용할 수 있는 기간별 요약 PDF
- 전문가 또는 상담기관 연결
- 사용자가 선택한 기록만 신뢰인에게 공유

## 6. 우선 보류할 기능

다음 기능은 운영 및 안전 부담이 크거나 Lumine의 차분한 기록 경험을 해칠 가능성이 있어 초기 로드맵에서 제외한다.

- 익명 커뮤니티
- 사용자 간 개인 메시지
- AI 심리상담 챗봇
- 진단명 또는 위험 점수를 직접 보여주는 기능
- 경쟁형 연속 기록 스트릭

## 7. 권장 실행 순서

1. 작성 임시 저장과 미동기화 기록 표시
2. 기록 및 마음 상태 확인 리마인더
3. 주간·월간 마음 리포트
4. 달력형 기록 탐색
5. 감정 맥락 태그
6. 개인화된 작은 행동
7. 개인 안전 계획
8. 스마트워치 기반 마음 체크인 제안

각 기능은 구현 계획을 세우기 전에 사용자 문제, 성공 지표, 안전 정책, 데이터 요구사항을 별도 요구사항 문서로 확정한다.

## 8. 향후 플래닝 시 확인할 지표

- 첫 일기 작성 완료율
- 가입하지 않은 사용자의 첫 기록 완료율
- 게스트에서 회원으로 전환한 비율
- 가입 후 게스트 기록 동기화 성공률
- 7일 및 30일 재방문율
- 사용자당 주간 기록 일수
- 마음 상태 확인 완료율과 중도 이탈 문항
- 결과 화면에서 감정 일기로 이어지는 비율
- 도움 요청 화면에서 전화 또는 메시지 공유를 실행한 비율
- 위로 문구에 대한 긍정 피드백 비율
- 스마트워치 연동 동의율과 권한 유지율
- 패턴 변화 알림에서 감정 일기 또는 마음 상태 확인으로 이어지는 비율
- 스마트워치 알림의 `도움 됐어요`·`지금은 아니에요` 응답 비율
- 알림 해제율, 권한 철회율, 반복 무응답률

안전 관련 지표는 일반 전환율 최적화와 분리하여 관리하고, 도움 요청을 줄이는 방향으로 최적화하지 않는다.
