# 마음 상태 확인 + 감정 일기 MVP 디자인 문서

## 1. 디자인 목표
- 사용자가 앱에 들어왔을 때 평가받는 느낌보다 이해받는 느낌을 먼저 받아야 해요.
- 전체 경험은 조용하고 단정해야 하고, 과한 경고나 과장된 긍정 표현은 피해야 해요.
- 결과 화면은 `문제 판정`이 아니라 `지금 상태를 함께 정리해주는 화면`처럼 보여야 해요.

## 2. 톤 앤 매너
### 2.1 기본 방향
- 차분함
- 공감
- 위로
- 안전감

### 2.2 문장 스타일
- UI 문장은 부드러운 구어체를 기본으로 써요.
- 종결 표현은 `~입니다`보다 `~해요`, `~같아요`, `~해볼까요`를 사용해요.
- 사용자가 잘못했다는 인상을 줄 수 있는 표현은 피해요.

### 2.3 금지 표현
- `우울증 검사`
- `진단 결과`
- `고위험군`
- `중증 상태`
- `비정상`

### 2.4 권장 표현
- `지금 마음을 가볍게 살펴봐요`
- `요즘 많이 지치셨던 것 같아요`
- `오늘 감정을 남겨볼까요`
- `혼자 버티기보다 도움을 받아도 괜찮아요`

## 3. 정보 구조
- 로그인 / 회원가입
- 첫 상태 확인 시작
- 질문 진행
- 결과 / 위로
- 오늘의 감정 일기
- 지난 기록 / 변화 보기
- 안전 도움

## 4. 화면별 UX 방향
### 4.1 로그인 / 회원가입
- 소셜 로그인은 카카오, 구글 2가지만 보여줘요.
- 첫 화면 카피는 `지금 마음을 기록으로 남겨봐요`처럼 목적이 바로 전달되게 해요.
- 가입 보완 정보 입력은 최소 단계로 유지해요.

### 4.2 상태 확인 시작 화면
- `검사 시작`보다 `지금 상태 살펴보기`에 가까운 표현을 사용해요.
- 예상 소요 시간은 짧게 알려줘요.
- 의료적 진단이 아니라는 안내는 넣되, 겁주는 방식이 아니라 참고용 안내 톤으로 보여줘요.

### 4.3 질문 진행 화면
- 한 번에 한 질문만 보여줘요.
- 진행률은 숫자보다 흐름형 인디케이터를 우선해요.
- 선택 버튼은 충분히 크고, 현재 선택 상태가 분명해야 해요.
- 민감 문항 앞에는 짧은 완충 문구를 둘 수 있어요.
  - 예: `조금 조심스러운 질문일 수 있어요. 괜찮은 만큼만 답해도 돼요`

### 4.4 결과 화면
- 점수 자체를 전면에 내세우지 않아요.
- 기본 구성은 아래 순서예요.
  1. 상태 해석 카드
  2. 지금 해보면 좋은 행동
  3. 필요 시 도움 연결
- 내부 진단명은 노출하지 않아요.
- 사용자에게는 상태를 설명하는 문장으로 번역해서 보여줘요.

### 4.5 감정 일기 화면
- 오늘의 감정 3개 선택 영역을 먼저 보여줘요.
- 그 아래에 자유 입력 영역을 배치해요.
- 화면 인상은 `기록`에 집중하고, 분석 느낌은 최소화해요.
- 하루 한 번 기록이라는 사실은 부드럽게 안내해요.

### 4.6 저장 중 위로 문구 오버레이
- 저장을 누르면 즉시 위로 문구 오버레이가 떠야 해요.
- 오버레이 문구는 오늘 고른 감정 3개를 바탕으로 생성해요.
- 저장이 빨리 끝나도 오버레이는 최소 1초 유지해요.
- 로딩 표시가 기술적으로 느껴지지 않게, 짧은 위로 문장과 미세한 움직임 정도만 사용해요.

### 4.7 안전 도움 화면
- 가장 먼저 보여야 하는 건 판단이 아니라 행동 버튼이에요.
- 사용자가 당장 누를 수 있는 CTA를 상단에 둬요.
  - `109로 연결하기`
  - `119 도움 요청하기`
  - `주변 사람에게 알리기`
- 화면 전체 톤은 강한 공포보다 차분한 긴급성에 가까워야 해요.

## 5. 카피 원칙
- 결과는 확정형보다 해석형으로 작성해요.
- 사용자가 자기 상태를 비난하게 만드는 문장을 피해야 해요.
- 안전 관련 안내는 돌려 말하지 않고 분명하게 써요.

예시:
- `조금 오래 지쳐 있었던 것 같아요`
- `요즘 혼자 버티는 시간이 길었을 수 있어요`
- `지금은 혼자 견디기보다 도움을 바로 받아보는 게 좋아요`

## 6. 시각 스타일 원칙
- 의료 앱 느낌이 강한 새하얀 화면과 경고색 중심 조합은 피하는 편이 좋아요.
- 전반적으로 부드러운 명도 대비와 안정적인 여백 구조를 사용해요.
- 상태 구분이 필요할 때도 빨강만으로 의미를 전달하지 않아요.
- 감정 기록 화면은 쓰기 쉬운 여백과 낮은 인지부하가 중요해요.

## 7. 상호작용 규칙
- 질문 응답은 즉시 시각 반응이 있어야 해요.
- 제출/저장 중에는 중복 탭을 막아야 해요.
- 네트워크 오류 문구도 딱딱한 시스템 메시지보다 사용자 맥락형 문장으로 보여줘요.
  - 예: `저장이 잠시 늦어지고 있어요. 한 번 더 시도해볼까요`

## 8. 접근성과 안전 UX
- 색만으로 상태를 구분하지 않아요.
- 모든 주요 버튼은 명확한 텍스트 라벨을 가져야 해요.
- 위기 도움 CTA는 최소 터치 영역을 충분히 확보해요.
- 스크린리더에서 질문 번호, 질문 내용, 선택 상태가 자연스럽게 읽혀야 해요.
- 움직임 축소 설정에서는 오버레이와 전환 애니메이션을 최소화해요.

## 9. 반응형 원칙
- WebView 기준 모바일 우선으로 설계해요.
- 질문 화면은 태블릿에서도 단일 컬럼을 유지해요.
- 기록 목록과 변화 요약 화면은 큰 화면에서만 2열 확장을 허용해요.
- 키보드가 열렸을 때 입력창과 저장 버튼이 가려지지 않아야 해요.

## 10. 디자인 산출물 기준
- 핵심 플로우 와이어:
  - 로그인
  - 상태 확인 시작
  - 질문 진행
  - 결과
  - 감정 일기 작성
  - 저장 중 위로 문구
  - 안전 도움
- 컴포넌트 기준:
  - 감정 선택 칩
  - 질문 선택 버튼
  - 상태 해석 카드
  - 위로 문구 오버레이
  - 안전 도움 CTA 카드
